# Changelog

All notable changes to Filterest are documented here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

**Where this history starts.** Filterest has been released from this repository
since 9.3.3, and that is where this file begins. Earlier versions were released
from the shared version line of the private maintenance shell, and their history
stays there. Each entry below is the product part of that release; the newest
release is also described in
[RELEASE_NOTES.md](app/docs/publication/RELEASE_NOTES.md), which every release
overwrites.

Dates are the local (Europe/Helsinki) date on which the version was published.

The shared boundary that already refuses a signed-out sign-in refuses an expired one in the same question and against the same reading of the clock. The deadline is a moment and not a length, which is the whole of the design: comparing a sign-in's start against whatever the setting says today would leave the setting itself as a way to extend a sign-in — sign out under a one-day limit, keep the cookie signed through a public route, then raise the limit, and the same cookie is accepted again once its refusal record has run out. The form now says "Connect two fields", with an information symbol that opens one sentence: a row of this dataset points at a row of another one, so the other row's information can be shown and the value stays valid, with the technical term in parentheses. The technical foreign-keys page keeps its own wording.
- **The application notices when a picture's file has left the disk** — A row could point at a picture whose file was long gone, and nothing said so: the picture simply did not appear, as on one site's About page. A check now reads the pictures and attachments rows refer to and reports the ones that are no longer in storage. It only reports: it never repairs and never deletes. It runs in the background after startup and on demand from the media tools screen, within a row limit and a time limit an administrator sets, spread between datasets in proportion to their size so small datasets are always checked completely. The last result stays on the screen, with a plain notice when a limit stopped the run. Files that no row uses can be reported too, behind their own setting, off by default.
- **The emergency command can also create the first administrator** — It could only restore an account that still existed, which is no help to a rebuilt or restored site that has none. Behind its own switch it now creates one, on the server, in a protected terminal: it names the site, the database and the account before acting, says whether the ordinary repair path is still open, demands a typed phrase when an administrator already exists, asks for the password and PIN without echoing them, and writes the account, its group, its credentials and an audit entry in one transaction or not at all. It can only add an account, never change one. The browser's first-run form and this command now share one definition of what an administrator is, so the two cannot drift apart.
- **Every dialog keeps the same distance from the screen's edges** — Each dialog used to state its own margin, so on a phone one stood 24 px from the edges while the rule said 16, and the height had three different answers across the product. One rule now keeps 16 px on all four sides, and a dialog states only its own maximum size. The stacked dialogs are sized by one owner instead of two that disagreed; both are pixel-identical to before.
- **Code that nothing used is gone** — A text no screen showed, a spacing value with no readers, four functions only their own tests called, and the card view's replaced details printer. Each was checked for a real caller first, and the safety rules those tests guarded are proven on the paths that are actually used.
- **The space above a dataset's header icon is yours to set** — The icon sat 12 px below the dataset tabs, with no way to change it. It now starts 40 px below by default, and an administrator adjusts that distance in the appearance palette under "Dataset header"; the page follows the slider without a reload. One named value carries it, so the stylesheet states the distance once and a site that never touches the setting still gets the new default.
- **An AI provider's key can be installed from the embeddings page** — Only one provider's key could be entered in the interface, and the other had to be written into a settings file on the server. The embeddings page now says whether a key exists for the site's chosen provider and, when none does, offers a field for it: what is sent to the provider is stated beside it, the key is written into the installation's protected settings and used at once, and it is never shown, echoed or logged again. Where an installation keeps its settings outside the application, the page says exactly that and changes nothing.
- **Every card renderer places a field's name the same way** — The rule that puts a short value's name beside it, and leaves a running text's name off, reached only one of the card's four renderers, so a detail tile still printed the name as a heading above the value. All of them now ask the same question in the same place, and the answer comes from the column rather than from the row being drawn. A card is shorter for it, and on a phone a field's name is no longer cut off in the middle.
- **The address says which view you are looking at** — Closing an article left "view=article_view" in the address, and the next search, sort or filter copied it onward, so a bookmarked or reloaded address reopened an article the person had left. Which view is showing was remembered in three places that could disagree. One of them now decides: after a view has finished rendering, the address and the remembered parameters are written together from what is actually on screen, including when a permission gives the person a different view than the address asked for. An article view with no rows keeps its own name, because that is a real state.
